新协议的骨架**立住了**：信息边界、槽时序、资源/ACK 记账、子流配对四组合同均通过可证伪的反例检查（49 项，含 6 项阴性对照）。

## 3 协议实现要点

- 动作空间固定 5 个：`PROBE(0) PROBE(1) SEND(0) SEND(1) HOLD`，顺序写进代码常量，防止轮次间漂移。
- 时隙顺序（`world.CWWorld.step`）严格按 v4 §3.3：
  1. 用**槽开始**的估计算 `u_t`；
  2. 采样 `x_t`（SEND）或读有噪 `h_t`（PROBE）；
  3. 用**真信道**在 `t` 时刻判成败（策略不可见）；
  4. 推进物理与信道；
  5. 槽末的观测**校正到 `t`**，再用已知 `u_t` 推到 `t+1`（`P' = A²P + σ_w²`）。
- `SchedulerView` 用 `__slots__ = ("__w",)` 存内部世界 ⇒ `view._w` / `view.world` / `view.env` 一律 `AttributeError`。
  **这一条改过一次**：初版用单下划线 `_w`，实际能被直接访问（反例 1a 抓到的）。
- 子流：`np.random.SeedSequence(root).spawn_key=(split_idx, episode)` 再 spawn 5 条（plant/channel/meas/csi/packet），
  打印完整 `spawn_key` 作为唯一 ID。

### 4.1 检查过程中改掉的真实缺陷（不是判据放宽）

1. **`served`/接口泄漏 ⇒ 已改**：`SchedulerView` 初版用单下划线 `_w`，`view._w._x_true` 可直达 ⇒ 改双下划线 `__w`。
2. **策略永不发送**：`task_aoi = -1`（从未观测）被我当成"最新"，导致 `max(aoi) < θ` 恒真 ⇒ 256 步零发送。改为 `_aoi_key()` 把"从未观测"映射为 `inf`。
3. **真值扰动错位一步**：`truth_override` 初版在 `step` 之前注入，而推进在 `step` 内部 ⇒ 扰动只影响本槽读数、又被演化覆盖。修正为**本槽任何读数之前**注入。
4. **静默降级不可见**：预算耗尽后 runner 退化为 HOLD，但没计数 ⇒ `always_probe` 的成本 1224.8 看起来像"策略差"，其实是**被预算截断后完全失控**。新增 `n_forced_hold` 列与两条恒等式，现在这在表里一眼可见。
5. **自检入口污染证据链**：`r0.main()` 初版在 `--skip-panel` 时**仍然** `mkdir` 并写 4 个文件，
   结果是每跑一次"只自检"就往 `results/` 里塞一份 `n_panel_rows=0` 的空 run。
   已改为 `--skip-panel` 直接打印后 `return`，**不落盘**（复跑验证目录未新增）。
   —— 这是 R45「只跑自检的入口不得触碰入库证据」的第二次复发，说明这条纪律必须当**默认写法**，而不是每次想起来才遵守。

### 4.2 判据自己错过的几次（已修正，供后人避坑）

- **反例 1d 原判据自相矛盾**：最初要求「只改真信道 `h` ⇒ 动作序列逐位不变」。这在 POMDP 里**不可能成立** ——
  改 `h` 会改交付结果，`ACK` 是合法观测，纯 AoI 策略也会分叉。已拆成三种形式：
  `1c` 只改 `x` ⇒ 整条序列不变（严格）；`1d` 改 `h` ⇒ **首次分歧之前**完全一致且分歧前有交付差异可解释；
  `1d′` 首次交付之前动作不变。
- **反例 4g**：要求 `m_nack ≠ m_hold`，实测 `m_nack` **恰好 0.0**。不是 bug —— `_ack_bump(−1.5)` 的后验均值
  解析解正好是 0。判据改为均值 + 方差两维（`m_ack > m_hold`、`m_nack ≤ m_hold`、`v_nack > v_ack`）。
- **反例 5b/5c 第一版**用「错误接收端成本更高」判定，FAIL。查下来是判据错：`R=0.1 ≪ Q=1` ⇒ `K≈2.8`、
  `|A−BK|≈0.73`，控制器把状态压到 `1e-3`，成本都在噪声地板，差值符号随机。改用估计误差 RMSE（5b）+ **结构检验**（5c/5d）。
- 该结构检验又迭代了 3 次才闭合，每次漏的都可独立验证：漏卡尔曼增益 K（差 9e-7）→ 漏过程噪声的作用（差 1.8e-8，两种实现的残差比值恰为 `A=1.01`）→ **漏 `K·x̄` 那一项在 x̄≠0 时不会被约掉**。最终写成完整解析式，不靠调容差通过。
- **反例 3d** 原要求「未测用户方差完全不变」，错：AR 演化本身会让它变。3d 改为只看被测用户收缩 >50%，严格对照放到 3e。
- **反例 3g** 原断言 `w4.t == 3`，错：被拒的 `SEND` 不应推进时间。改为 `w4.t == 2` 并在 detail 写明。
- 该结构检验又迭代了 3 次才闭合，每次漏的都可独立验证：漏卡尔曼增益 K（差 9e-7）→ 漏过程噪声的作用（差 1.8e-8，两种实现的残差比值恰为 `A=1.01`）→ **漏 `K·x̄` 那一项在 x̄≠0 时不会被约掉**。最终写成完整解析式，不靠调容差通过。

的 `aoi` 写成 `7.5`（实际 `7.8`；`7.5` 是 `ρ=0.98` 那行的值），还漏了一整行 `paced_age4 @ 0.85/0.8`。
`gates.json` 里 49 项**全是绿的** —— 因为它们测的是 `experiments/cw_v1/` 的代码，不测文档。

`doccheck` 做三件事：①逐格比对 (ρ, B/T, policy) → cost/probe/att/del/fhold/aoi；
②核对文档里声称的聚合数（49 项 / `n_fail=0` / `n_panel_rows=72` / `elapsed_s=1.27`）；
③4 个阴性对照（`cost+0.002`、`delivered+0.2`、`forced_hold+1`、policy 串格）必须全部被抓到。

★ 容差的选择本身也踩过一次：初版 `cost` 容差设 `5e-4`（"3 位小数的舍入上界"），
结果 `0.0755 → 0.076` 被判 FAIL（差 `5.31e-4`）—— **判据比被测物还严**。
放宽到 `6e-4` 后，另外单独验证了 `+0.002`（超容差 3.3×）仍被抓到 ⇒ 容差没有宽到失去分辨力。
