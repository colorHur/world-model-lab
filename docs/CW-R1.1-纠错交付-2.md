## 1 一件：一步预测与协方差（`pred_gates.py`，10 项 / 0 FAIL）

### 1.1 为什么先做这一件

v4.1 §2 写的是"前一件不过就停"。原因是**如果没有一个正确的预测器，后面所有"要不要发/要不要测"的
比较都建立在错的状态估计上**；而验收报告已经量到：零噪声、初值完全匹配、只 HOLD 一次时，
名为 `exact` 的模式误差 **0.0309**，名义模式 **0**。一个"更精确"的东西不可能在可精确求解的场景里更差。

### 1.2 关键推导（写在代码里，也写在这里）

本环境 `_advance_physics()` **一个时隙只推进一次、只加一次过程噪声**：

```
x_{t+1} = A x_t + B u_t + w_{t+1}
```

接收端在槽末要给出的是 `E[x_{t+1} | 到槽 t 末的信息]`，因此

```
x̂_{t+1} = A x̂_t + B u_t ,      P_{t+1} = A² P_t + σ_w²
```

**这两条就是精确的一步预测**。被撤回的 `exact` 分支假设"一个时隙推进两次"
（`x_{t+1} = A(A x_t + B u_{t-1} + w_t) + B u_t + w_{t+1}`），于是它

* 在状态里把控制量用两遍（`B u_{t-1}` 与 `B u_t`），
* 在协方差里把过程噪声加两遍（`A²σ_w² + σ_w²`）。

对一个**符号都可算**的系统，这不是"精度差异"，是**两次施加同一个动作**。

### 1.3 证据（全部机器可复算）

| 闸 | 判据 | 实测 | 什么错误能让它 FAIL |
|---|---|---|---|
| **P1** | 零噪声 + 初值匹配 + 纯 HOLD 6 步：`max|x̂−x|` 逐位 0 | `[0.0]×6` | 多做/少做一次映射；噪声加超过一次 |
| **P1c** | 把 `x̂_0` 偏 0.1 ⇒ 偏差必须非零 | 0.09999999999999998 | （阴性对照）P1 恒真时这条会 FAIL |
| **P2** | 零噪声 + 初值不匹配：偏差 `= A^k δ₀`（A=(1.01,1.03)） | 0.2525 → 0.26538，逐项 ≤1e-14 | 预测器若"复制真值"，偏差恒 0 ⇒ FAIL |
| **P3** | 有噪声 + 混合动作：`x̂/P̂` 与独立 Kalman 复算一致（中段 + 末点） | `mid_dx = mid_dP = end_dx = end_dP = 0.0` | 校正对象错一拍 / 先校正后滚动顺序反 / gain 用错方差 |
| **P3b** | 逐槽 40×2×2 = **160 个值** × 全程 | `max_abs_diff = 0.0` | 同上，且**只看末点会漏掉中途漂移** |
| **P4** | 1000 episode：`E[e²]/E[P̂] ∈ 1±3σ`（σ=√(2/N)=0.0447） | user0 **1.0244**、user1 **0.9861**（带 [0.866, 1.134]） | P̂ 系统偏大/偏小：漏 σ_w²、拿 Riccati 的 `P_ss` 顶替 |
| **P5** | 零噪声夹具必须被 `v11_validate()` 拒绝 | 2 条 `sigma_w` 报错 | 有人调 σ_w=0 去跑面板追 PASS |
| **P6** | `exact` 在 `CWWorld(...)` 与 `run_episode(...)` 两个入口都被拒 | 两处均 `ValueError` | 留一个"打开就更精确"的暗门 |
| **P7** | 复刻旧分支：零噪声第 2 步偏差 **== `B·K·x₀`**（解析值） | 解析 0.5996655284550136 / 实测 0.5996655284550135 | 偏差不是"一步控制量"量级 ⇒ 说明我对缺陷的归因错了 |
| **P8** | 物理不变式：每步 `P̂ ≥ σ_w²`（A=1） | 160 个检查点 0 违例 | 协方差递推写错符号/漏项 |

★ P4 里 **user1 从不发送**，所以它同时检验"长时间无观测时方差如何增长"——
这正是"一帧值不值"的核心量，本轮只验它算得对不对，**不回答它大不大**。

## 2 二件：外生事件的配对口径（`pairing_gates.py`，7 项 / 0 FAIL）

### 2.1 旧口径到底差在哪

旧实现里 `packet` / `meas` / `csi` 三条子流**按动作次数**取值：发 128 次的臂与发 64 次的臂
读的是同一条流的**不同位置**。分布相同（所以边际统计没错），但

* 不能声称"两臂在第 t 槽面对同一枚硬币"，
* 不能把"两臂都在 (t,i) 发了"当成同一事件的两次观测来配对。

验收要求二选一：按 `(episode, t, user)` 索引，或**明确写出耦合方式且不得声称逐时隙匹配**。
本轮两件都做了：**实现了 (t,i) 索引**，同时把旧口径保留为显式开关并写清它不能声称什么。

### 2.2 实现

`config.ProtocolConfig.event_pairing`：

| 值 | 语义 | 用途 |
|---|---|---|
| `"slot"`（默认） | 三条流在 episode 构造时**一次性预生成** `(horizon+1, n_users)` 矩阵，下标 = `(t, user)` | 新证据一律用它 |
| `"attempt"` | 按动作次数取流 | 只用于**重放** 2026-10-22 18:20 前的证据 |

★ `plant` / `channel` 两条流**没动**：它们本来就"每槽一次、与动作无关"。
★ `plant` 噪声仍是顺序取（一槽一个），因为它本来就按槽索引；`packet/meas/csi` 才是原来按次数取的。

### 2.3 证据

对比设计：策略 A **每槽都发 user0**（256 次），策略 B **偶数槽发 user0**（128 次）。
重叠点 = 偶数槽 128 个。比较三件事：送达与否、`p_true`、反推的量测噪声 `z = (y_t − x_t)/σ`。

| 闸 | 判据 | 实测 | 什么错误能让它 FAIL |
|---|---|---|---|
| **Q1** | 默认口径必须是 `"slot"` | `slot` | 默认值被改回按次数 |
| **Q2** | `slot`：128 个重叠点送达全同、`p_true` 全同、79 个双送达点 z 全同 | 128/128、128/128、**79/79**，`max|Δz| = 4.4e-16` | 抽样仍按次数 / 抽样引入策略相关量 |
| **Q3** | 样本量守卫：重叠 ≥64、双送达 ≥32 | 128 / 79 | 重叠为空 ⇒ Q2 恒真 |
| **Q4** | **阴性对照**：`attempt` 口径下同一比对必须出现不一致 | **41/128 送达不同、58/58 z 不同** | （这条 FAIL 就说明 Q2 没有分辨力） |
| **Q5** | 配对不改边际：送达率差 ≤ 4σ（σ=√(p(1−p)/n)，n=7680） | slot **0.49935** vs attempt **0.50208**，gap 0.00273 < 4σ=0.0228 | 预生成用错分布/错位 |
| **Q6** | 确定性 + 外生性：同种子两次构造矩阵逐位同；首槽 plant 噪声与策略无关 | 均 true | 预生成里混进策略相关量 |
| **Q7** | **回归**：`attempt` 口径逐位复现改动前 4 个参考例（含 trace hash） | 4/4 `equal` | 改配对顺手改坏旧路径 |

★ Q2 的 z 不能要求逐位相等：`y = x + σz` 而两世界 `x` 不同，`(y−x)/σ` 的舍入不同（实测差在第 16 位）。
判据用 1e-9 相对容差；`attempt` 下 z 的差是 O(1)，**区分度不受影响**（Q4 就是这条的证明）。
第一次写 Q2 时我直接比 `y_t`，FAIL —— 因为两策略的 `x_t` **本来就该不同**。判据比错了对象，见教训 **#86**。

### 6.1 ★ 一个被上一轮报成"全 PASS"的判据其实是 FAIL（S4）

`sched_gates` 现在 **15 项 / 1 FAIL**，FAIL 的是 **S4**：

> S4 真 CSI vs 常数 CSI：≥80% episode 动作序列不同 → 实测 **30/48 = 62.5%**

三件事必须一起说清：

1. **不是本轮改配对造成的**。用改动前的代码（`git stash` 回到 HEAD `3bc4989`）跑同一条判据，
   结果**一样是 62.5%**；`S4b` 里把同一 48 格用 `attempt` 口径再跑一遍，也是 **0.625**。
2. **上一轮 `RUNLOG` 写的"sched_gates 全 PASS"与实测不符**：在 `3bc4989` 上实测 13/14。
   最可能的机制是**只看输出尾部**（`tail` 里 S5–S10 全 PASS，S4 在更上面）。
   教训 **#88**：**判"全 PASS"必须以退出码 / `--json` 的 `n_fail` 为准，不许看尾部几行。**
3. **阈值不放松**。80% 是预注册的效应量门槛，实测 62.5% ⇒ 这条判据**未命中**，
   按"失败是结论"记录；**不改 80 去追 PASS**。

同时把"CSI 有没有用"这件事换个量报（S4b，只记录不作判据）：同一 48 格上，
真 CSI 版 `cost_true_per_step` 均值 **0.622315**，常数 CSI 盲版 **1.160420**，
**比值 0.5363**。⇒ **"动作序列不同率"只有 62.5%，但成本差是 1.86×** ——
这两件事不矛盾：CSI 的价值不在"每次都改动作"，而在"改的那几次改对了"。
所以 STATE 里"CSI 真能改变动作（100%）"的旧说法**必须降级**为"改变 62.5% 的 episode 动作序列"，
且**不许**再用"动作不同率"当"CSI 有用"的证据。
