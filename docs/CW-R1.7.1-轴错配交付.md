## §0 判词（引用时照抄）

**`AXIS-SWAP-CONFIRMED`。** `plan_dp.build()` 的 SEND 分支存在**轴错配**：`i=1` 时"用户 1 的送达更新"被
施加到**用户 0 的 P 轴**上。修复后同一套新判据 `A0–A6` **7/7 PASS**，最大偏差 **−0.060%**（对角）/ **−0.0005%**（非对角）；
旧实现在**非对角**上高估 **+13.8%…+44.3%**、`nf` 从 24 到 96 完全不收敛。

**R1.7 的 `DP-TAIL-REJECTED` 不撤销**：它指**那一版实现**。本轮只是把它的根因挖出来、把参考物换对、
把旧实现留成活体对照。`plan_ref` **仍未接线**，面板**仍未跑**，`N1/N2` **仍未读**。

## §1 根因（一行代码）

```python
# 旧（plan_dp.py build()，R1.7）
d = self._bil(Vprev, m_del[i], m_hold[j])[:, :, bs]      # j = 1 - i
```

`_bil(Vprev, m0, m1)` 的 `m0/m1` **恒对应 Vprev 的第 0/1 条 P 轴**（= 用户 0 / 用户 1）。
所以：

| i | 传入 | 实际含义 | 对不对 |
|---|---|---|---|
| 0 | `(m_del[0], m_hold[1])` | 轴0 用用户0 的送达、轴1 用用户1 的 hold | ✅ 对 |
| 1 | `(m_del[1], m_hold[0])` | **轴0 用用户1 的送达**、轴1 用用户0 的 hold | ❌ 错 |

修复：

```python
maps = [m_hold[0], m_hold[1]]
maps[i] = m_del[i]
d = self._bil(Vprev, maps[0], maps[1])[:, :, bs]
```

旧行为保留为 `axis_mode="legacy_swap"`（**逐位复现**），只作阴性对照；`get_dp` 的缓存 key 已加 `axis_mode`。

## §2 为什么 R1.7 的三道闸全都看不见它

**这不是"闸不够多"，是三道闸各自缺一个维度，缺的恰好是同一个。**

| R1.7 的闸 | 缺什么 | 后果 |
|---|---|---|
| `D3` 可采纳性 vs `brute` | 参考物是**开环最优**（`brute` ≥ 闭环真值） | DP 比真最优高 **+44%**，比 `brute` 只高 **+2.9%** ⇒ 阈值 1e-9 虽会 FAIL，**量级被参考物自身的水分掩盖** |
| `D4` vs `round_robin` | 参考物是**某个策略**，同理 | 同上 |
| `D1a/D1b/D2/D5` + 全部 case | 全部在 **`P0=P1`**（对角）上 | 轴错配在对角上只露 **+0.44%（τ=3）**，非对角露 **+15%（τ=2）** |
| `D6` 变异 M2「交换两用户轴」 | **它把这个 bug 修好了** | 旧实现的 `i=1` 分支把轴反过来，M2 再翻一次 ⇒ 恰好变正确 ⇒ `caught=false`（R1.7 记为"漏抓"） |

★ **本轮的教训（新增，编号留待台账）**：
> **"两个用户对称"这件事必须在闸里被显式破坏一次。** 只要有一条判据把 `P0` 和 `P1` 设成相等，
> 任何"用户轴与参数位置错配"的缺陷在它面前**恒等不可见**。这不是阈值问题，是**特征缺失**。

（−0.06%）。因为错配把"用户 1 的送达"压到轴 0 上，当用户 0 本来就更陈旧时，`min` 会挑另一支。

断言只能是"**不再有 +13.8%…+44.3% 的高估**"，不能写"DP 已精确"。

## §4 加密行为（A4）：为什么能判"结构性"

`solve` 点 `τ=4, b=4, (0.002, 0.05)`，真最优 `0.14925100`：

| `nf`（细段点数） | 修复版 | legacy |
|---|---|---|
| 24 | −0.0063% | **+44.259%** |

修复版缩了 **12 倍**（是离散化）；legacy 两档差 **0.04 个百分点**（与网格无关 ⇒ 结构性错）。
这是 R1.7 的 `D5` 想抓但没抓住的东西 —— 它当时抓的是"整体 1.346 倍不收敛"，却没定位到**哪一处**。

## §6 本轮自己的四处错（照实记）

| # | 错 | 发现方式 | 后果 |
|---|---|---|---|
| 1 | 第一个"精确参考"脚本里，用户 `j` **没有推进物理噪声**（只更新了发帧的那个用户） | 手算 `τ=2,b=1` 得 `0.0209611`，脚本给 `0.0201222`，差 0.0005 = 一个 `sw2` 的量级 | 该版 exact 低估 **1.2%–9.3%**，会把"修复版"判成高估。**只影响过程稿，未入库** |
| 2 | `A1` 第一版把**非对角** case 传给只接受单 `p` 的 `dp_gates.brute_opt`（隐含 `P0=P1`） | 直接 FAIL，读完 `bad` 发现比的是 `(p0,p0)` | 补双 `p` 版本 + 在对角上与旧版逐位对账（`max|Δ|=0`） |
| 3 | 把 `A2[legacy_swap]` 注册成独立 check | `n_fail` 里长期挂一条"故意失败" ⇒ 退出码恒 2 | 改为 `emit_gate=False`，legacy 的"必须被抓"由 A3 判 |
| 4 | 预注册 §3 引用 `D6` 的 M2 时说它"把 bug 修好了" | 是读代码推的，未单独验证 | 措辞已降为"**推测**：M2 再翻一次恰好变正确"，未写成实测 |
