## §1 一句话结论

R1.16 的机制判词 `MIXED-MECHANISM-AT-N10` 建立在 `share = E_term/Δr` 上，而该量随 `|Δr|` 变化
⇒ 换成一个**有界、与 `Δr` 解耦**的量 `ku = E_user/Mu` 后，机制**不随 episode 分岔**：

> **`Q_dir = DIRECTION-CONFIRMED:USER-NEGATIVE`** —— 10/10 个 episode 的 `ku < 0`，
> 中位 `|ku| = 0.354`，`p(0.5 端) = 0.00195`、`p(1/3 端) = 3.39e-5`。
> **帧维度 `DIRECTION-UNRESOLVED`**（6 负 4 正，`p = 0.754`）。

⇒ `exact` 相对 `approx` 的送达缺口，**在用户维度上是一个方向固定的机制**（把尝试搬到更差的用户上），
**在帧维度上没有一致方向**。R1.16 的"帧选择主导 3 个 ep"说的是**份额**，不是**方向**；两者不矛盾。

## §2 为什么必须换分母（这不是口味问题）

`decompose` 的三项满足恒等式 `E_user + E_frame + E_within ≡ Δr`（残差 2.8e-17 量级）。
于是 `share = E_term/Δr` 有两个结构性病：

1. 三项份额**和为 1** ⇒ 任一项高必然挤掉其他项，"份额高"不是独立信息；
2. `Δr` 是**净效应**，可以是两个大机制互相抵消后的残差。`ep103` 是现场：
   `E_frame = −0.00730` 与 `E_within = +0.00740` 在 `Δr = −0.00784` 里几乎完全抵消，
   份额随即给出 `sh_frame = +0.9311` 这种"看起来极强"的读数。

实测确认（`S1`/`S6`，**同一批计数矩阵**，只改送达结果 `nd_e`）：

| 版本 | `Δr` | `share_user` | `ku` |
|---|---|---|---|
| 原始 | −0.13562 | **+0.1951** | **−0.3000271** |
| `dr` 调到 ≈0 | +0.00065 | **−40.5875** | **−0.3000271** |
| （合成构造）`dr=0` | 0 | **NaN（不可定义）** | −0.6 |

⇒ `Δr` 从 −0.136 变到 +0.00065，`share` **符号翻转、量级放大 208 倍**，而 `ku` **逐位相同**。
`share` 的判词会因此从"H-A 帧选择"翻成"用户主导"——同一个 ep。

## §3 新量（预注册 §3）

```
m_i  = Σ_b(ni_e[i,b] − ni_a[i,b])          # 逐用户尝试数差
Mu   = Σ_i|m_i| / (2 N^E)                  # 用户级重分配 TVD 比例（**不含 nd_*，与 Δr 解耦**）
Mf   = Σ_ib|ni_e−ni_a| / (2 N^E)
ku   = E_user/Mu   = 2 Σ_i m_i(ρ_i−ρ_a) / Σ_i|m_i|
kf   = E_frame/Mf
```

**分工写死**：`ku` 回答"搬运本身多有害"（单位：送达率），**不**回答"解释了缺口多少"。
后者只有 `share` 能答，故降级为**描述**（限 `|Δr| ≥ 0.02` 子集，报 `n`）。

**有界性**：`ku = Σ_i (2m_i/Σ|m|)(ρ_i−ρ_a)`，权重绝对值和为 **2**（不是 1）
⇒ `|ku| ≤ 2·max_i|ρ_i−ρ_a| ≤ 2`。实测五组合成构造全部满足，构造值 `ku=−0.6 ≤ 0.8`。

## §4 结果（10 个 ep，`cells.json` 只读重算）

### §4.1 方向（主判）

| 维度 | `n_neg` | `n_pos` | `n_neu` | `median\|k\|` | `p(0.5)` | `p(1/3)` | 判词 |
|---|---|---|---|---|---|---|---|
| 用户 `ku` | **10** | 0 | 0 | **0.3536** | **0.00195** | **3.39e-5** | `DIRECTION-CONFIRMED:USER-NEGATIVE` |
| 帧 `kf` | 6 | 4 | 0 | 0.1457 | 0.754 | 0.153 | `DIRECTION-UNRESOLVED` |

两端 `p` 都 < 0.05 ⇒ 按预注册"两端同时满足才写确认"，用户维度**确认成立**。
帧维度两端都不显著 ⇒ `UNRESOLVED`，**不许**写成"帧机制不存在"（那是"测不出方向"≠"无效应"）。
