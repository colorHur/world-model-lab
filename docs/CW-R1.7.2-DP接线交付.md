**闭式为什么是"精确"而不是"上界"**：`b=1` 时只可能送达一次、只影响一个用户。
时刻 `k` 送达用户 `i` 后，从**第 `k+1` 步**起与"不送"的 `P` 之差为 `A_i²·g_i·P_i(k)`，之后按 `A^{2m}` 衰减
⇒ `saving(i,k) = q·p̂_i·g_i·P_i(k)·Σ_{m=1..τ−1−k} A_i^{2m}`；
代价对 `P` 线性可加、`V(·,0)` 只有一条路径 ⇒ `V(τ,0) − V(τ,1)` **恰好**等于 `max_{i,k} saving(i,k)`。
`W4b` 用逐步模拟（不用任何几何和）把它钉到 3.7e-16，所以"DP 的 drop 更大"只能是**乐观偏差**。

## 3 三个发现（按重要性）

### F1 ★ `_expect_after` 的 SEND 分支少推进了一个用户（老缺陷，已修）

`HOLD`/`PROBE` 两支都写 `P2 = A²P+σ_w²`（两个用户各推进一槽），`SEND` 支却写 `P2 = st.P.copy()`
再只覆盖被送用户 ⇒ **未被送用户的 `P` 原地不动**。后果：SEND 尾部成本被系统性低估。
实测 **0.97% / 1.13%**（`P=(0.01,0.02)`、`τ_tail=40`），而**要测的"一帧价格"本身只占尾部值 0.8%**
⇒ **缺陷量级 ≥ 被测量级**。

- 影响面：`R1.5 / R1.6 / R1.6.1` 的**全部** 面板、`G4`、`G8a`、`G5` 的动作序列都含此缺陷
  （每个 SEND 分支都偏"便宜"）。旧证据保留、不改写，标 `send_other_advance=legacy`，
  **不得**再用来支持"配速 / 一帧定价 / 3.8× 高估"的机制叙事。
- 修法：`send_other_advance="fixed"`（默认）；`"legacy"` 逐位复现旧行为，只作 `W0c` 活体对照。
- 回归：`r1_4_contract` **20/0**、`eval_gates` **14/0**（1.67 s）。二者**都不走** `_expect_after`，
  只能证"契约/评价器没被碰坏"，**不能**证"修 SEND 分支没影响别处"——受影响的恰恰是 `plan_gates`，
  而它本轮**没跑**（链在 `W4` 就停了）。

### F2 ★ "平滑" 不等于 "尺度对"：`G8d` 一族闸有共同盲点

`W1`（= `G8d[dp]`）**PASS**（平坦 0.78%、无上升），`W4` **FAIL**（价格高 8–51%）。
两条闸测的是不同东西：前者问"预算多给值不值钱"，后者问"值多少钱"。
⇒ **新纪律**：任何"值函数对预算有价格"的闸，必须配一条**尺度证书**
（拿闭式/穷举的已知答案代验量级，台账 R12），并且**证书本身要自检**（`W4b`）。

### F3 ★ "解析尾部把一帧高估 3.8×" 这个叙事**没有复现**

同一工作点（`τ=128`、`P=0.01`、`b=64`、`p̂=0.5`），两套 plant 的比值**符号相反**：

| plant | 解析边际价值 | DP 边际价值 | 解析/DP | 按预注册 §4 分档 |
|---|---|---|---|---|
| `bounded_plant()`（面板用） | 0.008153 | 0.024286 | **0.336** | 解析**低估** ≥2× |
| `R0_DEFAULT`（`A=(1.01,1.03)`） | 0.001720 | 0.000379 | **4.539** | 解析**高估** ≥2× |

两者都不等于 R1.6.1 报的 **0.0225**（该数字的口径没有随证据落盘，无法复现）。
⇒ **"3.8× 高估 ⇒ 规划器推迟花帧"这条机制链站不住**；在 `W4` 判 DP 不可采纳的前提下，
**两套价格都不能当机制证据**。
