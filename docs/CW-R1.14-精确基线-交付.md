## 0. 一句话

**`ack_mode="approx"` 的信道信念严重过度自信**（自称方差只有真实误差的 1/5.9），
**`exact` 的标定误差 8.7%**（四层口径同向）；但把 exact 升为基线**不是白拿**：
在同一规划器下它的**送达少 18.4%（8/8 格）** ⇒ 判词是「标定更好」+「一条交易」，不是「更好」。

## 1. 决策：选 A（精确升基线），否掉 B（把方向比改成 `(m,v)` 的函数）

预注册 §2 写在见数之前，此处只复述结论，不改写：

- **B 否**：精确后验的价格已被测过（321 点 / 一维 / 确定性 / 约 2 ms·步⁻¹）⇒ 算力上没有"必须近似"的约束；
  要拟合 `(m,v)` 的函数只能拿精确后验当参考物反推，**参考物已在手上**；且 `m=+1` 处 exact 比值 3.448
  而 `p/(1−p)=7.35`（差 2.1×）⇒ 任何解析候选式都不成立，B 只能退化成查表 = 更差的网格。
- **A 的条件**：只声称"信息模型合法"，**不声称收益**。本轮实测证明这个自我限制是对的（见 §3）。

## 2. 硬结果 `M2`：标定（本轮唯一的**有分辨力**新证据）

`R_var = mean((H−m)²) / mean(v)`，理论值 **1**（全方差分解，对预测分布同样成立）。
`H` = 真实 `log h`，`m,v` = 调度器可见的 `h_mean/h_var`，**同一时刻**（闸 `4w` 钉住对齐）。

| 口径 | approx（旧基线） | exact（新基线） | \|R_var−1\| |
|---|---|---|---|
| **逐格中位（主口径）** | **5.939**（格值 5.06–8.67） | **0.913**（0.69–1.19） | **4.939 vs 0.087** |
| 全池化 | 6.451 | 0.915 | 5.451 vs 0.085 |
| 逐 ep 中位 `ep100` | 5.879 | 1.007 | 4.879 vs **0.0066** |
| 逐 ep 中位 `ep101` | 6.493 | 0.792 | 5.493 vs 0.208 |
| 逐用户中位 `u0` | 4.908 | 0.862 | — |
| 逐用户中位 `u1` | 7.214 | 0.820 | — |

- 四个层级（格中位 / 池化 / 两 ep）**符号全同** ⇒ 判词 `EXACT-CALIBRATED-BETTER`（不是 `POOLING-CONFLICT`）。
- 描述量（**不是判据**）：`mean_z2` 中位 **8.250 vs 0.921**；`P(|z|>3)` 中位 **0.204 vs 0.000**；
  `P(|z|>2)` 中位 **0.399 vs 0.030**。⇒ approx 有 **20%** 的"用户-槽"落在自称 ±3σ 之外，exact 一个都没有。
- 机制读数（逐用户中位）：approx 自称方差 `mean_v` = **0.333 / 0.383**，而真实误差 `mean_err2` = **1.685 / 2.593**
  ⇒ **自称比现实紧 5.1× / 6.8×**。exact：`0.456/0.444` vs `0.398/0.376`。

**这不是"方差尺度偏小"，是"均值跑飞"。** 若只是方差偏小，调 `ACK_VAR` 就能修（R1.13 已证明 0/16 不行）；
真实误差是自称方差的 5–7 倍，说明 `m` 长期落在离真值很远的地方 —— 这正是 `±1.0/−1.5` 这个**没有依据的方向比**
在 `p→1`（`I→0`）区继续推均值造成的。`exact` 在该区几乎不动，所以结构性没有这条通道。

## 3. 交易（必须与 §2 同时报，R17 纪律）

| 量 | approx | exact | 差 |

| 尝试帧逐用户 | 546 / 448（偏 u0） | 489 / 512（更均衡） | — |
| `p̂` 下限中位 | 0.0689 / **0.0075** | 0.2058 / 0.1387 | 不再塌到 1e-2 以下 |

**可采纳**：标定变好（§2）；送达变少（8/8，`p=0.0078`）；`cost_true` 方向**测不出**（中位 \|Δ\| < floor）；
逐用户代价与 `aoi` **符号相反** ⇒ 只能写"交易"。

**不可采纳**：任何"exact 更好/更差"的整体判断；任何"ACK 不重要/信息模型无所谓"的推论（本轮没有关 ACK 的臂）；
任何显著性主张（**有效独立单元 = 2 个 episode**；槽间强自相关，256×2×8 个槽不是样本量）。

**为什么"标定更好反而送得更少"**：本轮**不解释**（无证据）。但有一条**可检验的候选**：
`p̂` 这一消费面在 approx 下被系统性放大（过度自信 ⇒ `p̂` 更极端），因此同一个 `LINE_EFFECT=0.20` 阈值
在两种信念下**筛出的是不同批次的帧**。要判它，必须看**逐尝试的 `p_true` 分布**——本轮没记（见 §5）。

## 6. 自伤清单（8 条，全部如实记）

1. **参照物索引错**（最贵的一条）：`identity_check` 第一版按 `ack_mode` 索引 R1.13 的 `cells.json`，
   而 `0.63/1.000/1.726` 三臂的 `ack_mode` **都是 `"approx"`** ⇒ 字典后写覆盖，只剩 `1.726`
   ⇒ 拿 1.726 对 0.63，报 `approx 0/8`。**一个 66 s 的正式 run 因此作废**（目录留档 + `_SUPERSEDED.md`）。
   教训：**参照物的键不是唯一标识时，对账会静默地比到另一个东西上**（#85 同族）。读 FAIL 明细才发现。
2. **`4v` 判据对象错（恒真）**：第一版用"动作序列哈希"判"参数有没有被消费"，但动作是**手写常量表**
   ⇒ 恒真。读完 FAIL 改成**信念终值**（#46 族：判据要指向能被该参数影响的东西）。
3. **`4v` 首跑崩**：为确定性成败把 `_log_h_true` 强推 ±30，随后 PROBE 读数落在网格 `[−8,8]` 外 ⇒
   高斯似然全域下溢 `ValueError`。**是测试构造的问题**，但同时暴露一个真实行为差异：
   **exact 对支撑外读数是硬报错，approx 是软退化**。本轮不改（改 = 换基线），记在此处限制节。
4. **手算预言错 2×**：预注册 §0 手算 approx 的 `v` 不动点 ≈ 0.19，实测 `mean_v` **0.333/0.383**。
   方向对（远小于 1）、量级错。⇒ 手算只当方向判据（R14）。
5. **`mainline_config` 第一版默认 plant 写成了 dataclass 默认**（`R0_DEFAULT`，开环不稳定），
   与面板世界不一致；写入口脚本时发现，改 `bounded_plant()` + 闸 `4u` 加 `plant_is_bounded`。预注册 §8-2 已留痕。

## 7. 限制（写进论文/汇报时必须带）

1. **`n_ep = 2`**：任何"系统性"都要加 episode 才有资格说（`p=0.0078` 只是 8/8 的配对符号检验）。
2. `cost_true` 的方向**没测出**（中位 \|Δ\| 0.0246 < floor 0.0333）；不许把它写成"exact 更贵"或"更便宜"。
3. **规划器不是为 exact 调的**：`0.05/0.20/1.5/0.95`、`LINE_EFFECT=0.20`、`grid="r173"` 全部在 approx 信念下开发
   ⇒ 本轮的 exact 臂是"新信息模型 + 旧规划器"，**混了一个未受控的变量**。
4. exact 对支撑外读数**硬报错**（见 §6-3），部署口径必须写明（工作域 `|log h| ≤ 3`，网格 `[−8,8]`）。
5. `R_var` 的 exact 值 0.913 略**保守**（−9%），逐格 0.69–1.19；未追究成因（网格截断解释不了 −9%）。
