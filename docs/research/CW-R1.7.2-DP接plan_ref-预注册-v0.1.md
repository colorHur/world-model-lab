## 0 一句话

R1.6.1 的机制量级是「解析尾部把多花一帧定价 **0.0225**，而一帧的收益上界只有 **0.006**（3.8×）」
⇒ 规划器推迟花帧。这个 3.8× 有两个互斥来源：
**(A) 解析尾部的算术残差**（R1.6.1 已修一批、R1.7 又发现轴错配）；
**(B) 真实的预算价格结构**（一帧确实值 0.0225）。
本轮把尾部换成 DP 后重测 `price/benefit`：**只有 (A) 才允许说"G8a 的失败是算错"**。
判词按这条分档，不看面板收益。

## 2 改了什么（实现层，逐条可复算）

1. **`PlanRef(tail=...)`**：新增 `tail ∈ {"paced", "dp"}`。
   - `"paced"` = R1.6.1 的解析尾部（`_paced_sumP`），**默认值不变**；
   - `"dp"` = 把 `_terminal` 里的 `q·Σ sumP` 一项换成 `DPTail.value(P, bud, steps)`
     （后者已含 `q` 因子：`V_τ = q(p0+p1) + min{...}`）。
   - `q·Σx̂²` 与 `r·Σu²` 两项目**不动**（同一分解，理由见 `_terminal` docstring）。
2. **模块级默认** `plan_ref.TAIL_DEFAULT = "paced"`；只有 `r1_7_2_dp_wire.py` 在闸/面板期间
   临时置 `"dp"`，并在 `finally` 恢复。运行前打印、证据里落盘实际生效值。
   ⇒ 其它入口（`r1_5_plan` / `r1_6_plan` / `r1_6_1_plan` / `r1_7_1_audit`）**行为零改动**。
3. **DP 的信道信念 `p̂` 冻结在 episode 起点**（`self._dp is None` 时用当次 `telemetry` 建一次）。
   - 为什么不是"每槽重建"：`_advance` 每步都改 `mh/vh`，`_terminal` 每槽被调 ~10² 次
     ⇒ 按 0.02 量化缓存会**每槽多次重建**（0.174 s × 10²），本机 CPU 不可行。
   - 代价**必须量化**：`W3` 在若干 `(mh,vh)` 上比 `price(p̂_slot)` 与 `price(p̂_prior=0.5)`。
   - ★ 这是 R1.7 近似 #1（"槽初冻结"）的**进一步收紧**，写进证据 meta 的
     `phat_freeze="episode_prior"`，不得在正文里说成"逐槽 p̂"。
4. **`b_cap = tau_max = horizon`**：DP 的饱和律是 `b ≥ τ ⇒ V_τ(·,b)=V_τ(·,τ)`，
   `horizon=256` ⇒ `b_cap=256`；`value()` 里 `b` 超出 `nb-1` 会被夹紧，故必须 `b_cap ≥ τ`，
   否则 `b∈(b_cap, τ)` 这一段会被**静默压平**（`W1` 会抓到）。
5. **`G4` 的口径说明（先说清）**：`p̂` 冻结在 episode 起点后，DP 与 `M` 无关 ⇒
   `G4` 的"M 加倍稳定"**部分被结构性地满足**。因此 `G4` PASS **不能**单独证明
   "估计量方差小"，只能证明"规划器没有未播种的随机源、且换人动作不靠少采样"。
   这条限制写进判词，不许写成"G4 通过 ⇒ 规划器稳健"。

**没有改的**：`q/r/σ_w/σ_meas/B/κ`、`c_probe=c_data=1`、`event_pairing="slot"`、`horizon=256`、
`episode 100–107`、`H_PLAN=5`、`M_SAMPLES=32`、`G4` 的 0.90/10%、`G8a` 的 CV<0.30、
`G8d` 的 ≤10%/0 对、`G8d2` 的 >30%、`dp_gates.py`（R1.7 历史闸）、`dp_audit.py`（R1.7.1 历史闸）。

## 4 归因规则（看数前写死，这是本轮真正的产出）

**主归因比值（v2，见 §7 更正 1）**：`ratio = price_analytic / price_dp`（同点、同 `τ`、同 `b`）。

| `ratio` | 允许的表述 | 禁止的表述 |
|---|---|---|
| `≥ 2` | "解析尾部把一帧**高估 ≥2×**" ⇒ `G8a` 若仍 FAIL，**可**归因于算术（来源 A） | 不得写"尾部已修好所以配速该好" |
| `0.5 ≤ ratio < 2` | "两套尾部**同量级**" ⇒ 推迟花帧是**结构性**的（来源 B），`G8a` **不得**归因于算术 | 不得写"价格问题已解决" |
| `< 0.5` | "解析尾部把一帧**低估 ≥2×**" | 不得写"DP 与解析一致" |

**次要诊断**：`price_dp / benefit_imm`（`benefit_imm = q·p̂·g·P`，一阶即时）。
★ 这个比值**不能**单独作为"高估"的证据（见 §7 更正 1 的量纲说明），只能报数、不据此分档。

**分层报告义务**：面板四格照跑，但 `plan_probe` 与 `plan_noprobe` 的配对差
**只作为开发诊断**（8 集/格，不是确认集）；`N1`/`N2` 只在链全过时读。
**本轮允许的判词只有三类**：`DP-WIRED-PRICE-STRUCTURAL`（`0.5≤ratio<2`，即推迟是结构性的）、
`DP-WIRED-PRICE-OVERSTATED`（`ratio≥2`，解析高估）、`DP-WIRING-REJECTED`（`W0/W1/W1b` 任一 FAIL）。

## 5 否定条件（什么会让本轮结论作废）

1. `W0` 不一致 ⇒ 接线错，**面板结果整份作废**（不看收益，不看判词）。
2. `W1` FAIL ⇒ DP 在预算维度没有价格 ⇒ 与 R1.6.1 同病，链停在 1，不跑面板（省时间，且避免"用错的值函数做收益表"）。
3. `W1b` 不 FAIL ⇒ `W1` 无分辨力 ⇒ `W1` 的 PASS 不算数，链也停。
4. `W3` 显示 `p̂` 冻结代价 >30% ⇒ §2.3 的近似被推翻 ⇒ 只报 `W2` 的价格，**不报面板**。

## 7 事后修改记录（★ 跑数后只许追加，不许改上文）

### 7.1 更正 1 —— 写卡后 ~10 min、**任何测量之前**（量纲错误）

初稿 §4 用 `price_dp / benefit_imm` 分档，其中 `benefit_imm = q·p̂·g·P` 是**一阶即时**收益。
这是错的：`price_dp = V_τ(·,b) − V_τ(·,b−1)` 是**边际价值**（这一帧在未来 `τ` 步里被最优使用的
全部收益，含期权价值），它与"一帧的即时收益"量纲不同。
⇒ R1.6.1 的 3.8×（0.0225 vs 0.006）**本身就不是"高估"的证据**，它可能只是"期权价值 > 即时收益"。

**更正**：主归因比值改为 `ratio = price_analytic / price_dp`（同点同口径，消除量纲问题）；
`price_dp / benefit_imm` 降为次要诊断，只报数不分档。

★ 这条更正是本轮第一个自查命中（台账 #42：动机句里每个数字必须指到具体那一格）——
上一轮把 3.8× 写成"解析尾部高估了价格"的结论，**前提就不成立**，本轮必须重述。

### 7.2 更正 2 —— 写卡后 ~10 min、**任何测量之前**（`M1` 空转风险）

`plan_gates.mutation_gates` 的 `M1` 把 `caught` 定义成 `n_probe == 0`，**不检查**未变异时
`n_probe > 0`。若 DP 臂本来就不探测，`G5a` 天然 FAIL、`M1` 被记"被抓"，实际是空转。
**更正**：链上 `M1` 加前置条件（见 §3 第 2 条）；`plan_gates.py` **不改**（历史闸留档）。
