## §1 缺陷（R1.10 已定位，本轮修）

`experiments/cw_v1/world.py` `CWWorld.step()` 内，`i` 被三次赋值：

| 行 | 语句 | 作用域 |
|---|---|---|
| 402 | `i = act.user`（`if act.kind == "SEND"`） | SEND/NACK **两支都应**用这个值 |
| 428 | `for i in range(self.n_users):`（接收端名义滚动） | **循环泄漏**，结束后 `i = n_users − 1` |
| 443 | `i = act.user`（`if act.kind == "SEND" and delivered`） | 只覆盖**成功**支 |
| 462 | `self._ack_bump(i, +1.0)` | = `act.user`（靠 443 救回） |
| **467** | **`self._ack_bump(i, -1.5)`** | **= `n_users − 1`，不是 `act.user`** |

⇒ 所有 NACK 的信道信念更新都落到**下标最大的那个用户**身上。
`n_users = 1` 时 `n_users − 1 = 0 = act.user` ⇒ 缺陷**恒等不可见**（R0 的 `4g` 就是单用户口径）。

**为什么现有闸全部 PASS 而缺陷仍在**（`#94` 闸的 plant 决定它覆盖哪一支）：

- `4g` / `4h` / `4i` 全部读 `_m_h[0]`，且 `4g` 的失败支判据是 `m_nack <= m_hold`。
  旧实现里 `SEND(0)` 失败 ⇒ 更新跑到 `u1` ⇒ `_m_h[0]` 停在先验 `0.0`，与 `m_hold = 0.0` **相等**
  ⇒ `m_nack <= m_hold` **仍然成立**。判据没写"必须**下降**"，所以看不见。
- 没有任何一条闸问"**这个更新落在谁身上**"。这正是 MEMORY 里那条：
  **只要判据从未显式破坏"两个用户对称"，用户轴与实参位置的错配就恒等不可见。**

## §3 闸（写死；判据先代已知答案验一遍量级）

### 4j **失败支的更新必须落在被送的那个用户身上**（旧实现必须 FAIL）

- 构造 `n_users = 2` 的 world，`_log_h_true[:] = −30`（强制失败，与 `4a` 同法：只改真值，不改子流），
  `use_ack_for_csi=True`，执行 `step(Action("SEND", 0))` 一次。
- 断言：`m_h[0]` **严格下降**（`< 0 − 1e-6`）且 `m_h[1]` **逐位不变**（`== 0.0`）。
- **旧实现**：`m_h[0]` 不动、`m_h[1]` 下降 ⇒ **FAIL** ⇒ 有分辨力。
- 预验（写卡时手算）：`_ack_bump` 的 `g = v/(v+ACK_VAR) = 1.0/(1.0+0.63) = 0.61288`，
  `y = 0 − 1.5 = −1.5` ⇒ `Δm = g·(y − m) = 0.61288·(−1.5) = −0.9193`，`v_new = (1−g)·1 = 0.38712`。
  ⇒ 期望 `m_h[0] ≈ −0.9193`、`v_h[0] ≈ 0.38712`。判据容差取 `1e-9`（这是解析值，不是拟合）。

### 4k **镜像方向**（**单独不构成判据**，必须与 4j 同时存在）

- 同一构造，`step(Action("SEND", 1))` ⇒ 断言 `m_h[1]` 下降、`m_h[0]` 逐位不变。
- ★ 明写：**旧实现在这条上恰好 PASS**（`n_users−1 = 1 = act.user`）。
  ⇒ 单靠 4k 检不出缺陷；4j 才是判别支。**"两个用户对称"必须被显式破坏一次**这条纪律的现场落地。

### 4l **逐用户归属恒等式 + 荒谬性检查**

- 构造两条真实 episode（`ep ∈ {100, 101}`，`seed = 2001`，`ack=on`，`ratio=0.5`，与面板同参），
  从 `run_episode` 的 `res.n_attempted_by_user` / `n_delivered_by_user` 取 runner 侧读数，
  从 `world.n_ack_by_user` / `n_nack_by_user` 取世界侧读数。断言：
  1. 逐用户 `n_attempt_i == n_deliver_i + n_nack_i`（SEND 是二值事件）；
  2. `Σ_i n_nack_by_user[i] == n_nack` 且 `Σ_i n_ack_by_user[i] == n_ack`；
  3. **荒谬性检查**：任一用户 `n_attempt_i − n_deliver_i > 0` 而 `n_nack_by_user[i] == 0` ⇒ FAIL
     （真实失败 > 0 而计数侧为 0，M1xx 那类缺陷的直接指纹）；
  4. runner 侧 `Σ_i n_deliver_i == n_ack`（两侧对账，**同一时点同一事件**）。
- ★ 明写 4l **不能**证明 `_ack_bump` 的实参正确（计数器和 `_ack_bump` 是两处代码）
  ⇒ 4l 只封"计数归属"，归属正确性由 4j/4k 的**行为**观察钉死。这是分工，不是冗余。

### R2 · 2026-10-24 07:5x — §3 的解析预验漏了 `step` 末尾的信道信念滚动

**当时已看见**：4j/4k 在**修复已经生效**的实现上报 FAIL，`m0[0] = −0.782209` 而卡里算的是 `−0.920245`。

**原因**：卡里的解析值只算 `_ack_bump` 单步，而 `CWWorld.step` 在它之后还有
`_m_h *= rho` / `_v_h = rho²·v + (1−rho²)`（`world.py:499-500`）。
`−0.920245 × 0.85 = −0.782209`，与实测**逐位吻合**（`rho=0.85 = rho_panel[0]`，4j 未显式传 `rho`）。

**处置**：判据拆成两段 —— `4j-1` 直接调 `_ack_bump`（不走 `step`）与解析式逐位对账；
`4j-2` 要求 `step` 后的值 = 裸效应经一步滚动（`×rho` / `rho²v+(1−rho²)`）逐位相等。
**判据变严了**（原来是"等于一个我算错的值"），不是放宽。

### R3 · 2026-10-24 07:5x — §3 未涉及、但被修复直接推翻的 4g

**当时已看见**：`4g` 由 PASS 转 FAIL，`v_after_nack == v_after_ack == 0.5567`。

**原因**：旧判据 `(m_nack <= m_hold) and (v_nack > v_ack)` **靠缺陷成立** ——
缺陷态下 NACK 从不作用于 u0 ⇒ `m_h[0]` 停在先验 0.0（等于 `m_hold`）、`v_h[0]` 从不收缩。
修复后同一条伪观测（同一 `ACK_VAR`）把两者收缩到同一量 ⇒ `v_nack > v_ack` 必然 FAIL。

**处置**：改为 `m_ack > m_hold > m_nack` 且 `|v_nack − v_ack| < 1e-12`。
**新形式在旧实现上 FAIL**（`m_nack == m_hold`）⇒ 分辨力比旧形式强，不是放宽。
