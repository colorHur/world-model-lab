## 0 为什么这一轮是这件事

R5.4 的两个硬结论把论文逼到只剩一条可走的路：

1. 机制层（"测量占一个槽"）**不是新意**（N1 `arXiv:2503.13866v1` 2025-03 已做；N0 `arXiv:1807.04356v2` = IEEE **TCOM** 2019 已有"采样价+更新价+平均能量约束"）。
2. 实测层 **R4.0–R5.3 全部数值在 L2**（`build_engine_n` 的 `(m,v)` 充分性前提是"ACK 不进信道信念"）；
   主环境 `world.py` 是 **L1**（`ack_mode="exact"`，321 点网格精确贝叶斯更新）但**没有 L1 上的最优策略**。
3. ⇒ 三张主图**一张都没有合法数据**，缺的是**换对象**。

本轮就换对象：**在 L1 语义下**（ACK 会更新信道信念）做 `n=1` 的四臂对照。
图 3 的唯一合法数据来源就在这条对照上：**同一预算下两种信息的价格**——
`ACK` 是**零预算、零槽位**的信息；`PROBE` 是**耗槽**（`p=0` 时不吃量子但仍吃槽）的信息。
问的是：**免费 ACK 存在之后，耗槽探测还剩多少价值。**

## 1 四个臂的精确定义（本卡的核心，跑前写死）

设 `V_arm(τ, b)` = 在窗口 `τ`、预算 `b`（整数刻度，1 量子 = 8 刻度 = 1 次发送）下的最小期望任务成本
（`q·ΣP` 的折现和，终值 `t==1` 的 `q·ΣP`）。

| 臂 | 探测动作 | ACK 是否更新**信道信念** `(m,v)` | 含义 |
|---|---|---|---|
| `A0` | 无 | **否** | 历史全部 L2 面板用的基线（`A0`） |
| `A0p` | 无 | **是** | 只有免费 ACK 的 L1 世界 |
| `VL2` | 有（`p=0`，**占槽**） | 否 | L2 语义：探测有价值但 ACK 被浪费 |
| `VL1` | 有（`p=0`，占槽） | 是 | L1 语义：两路信息都在 |

由此定义三个**可测**的量（**都带方向，跑前推导**）：

```
IV_probe_L2 := A0  − VL2   ≥ 0      # L2 世界里"有探测"相对"没探测"的价值
IV_probe_L1 := A0p − VL1   ≥ 0      # L1 世界里"有探测"相对"没探测"的价值
IV_ack      := A0  − A0p   ≥ 0      # 免费 ACK 带来的信道信息价值
survival    := IV_probe_L1 / IV_probe_L2            # ★ 主量：ACK 在场后探测价值剩几成
```

**方向推导（必须先做，否则重犯 R5.0/R5.2 的"判据方向写反"）**：

- 同一动作集下，**信息更多不能更差** ⇒ `VL1 ≤ VL2`（`A0p ≤ A0`）⇒ 三个 `IV` 都 `≥ 0`。
- ⇒ `survival ∈ [0, 1]` 是**结构性质**，不是待测性质；`survival > 1` 只能是**近似误差**。
- ⇒ "ACK 吃掉探测价值" 的**正确方向是 `survival → 0`**，不是 `survival → ∞`。
- ★★★ **STATE §7.2 第 4 条把这件事写成 `IV_ack ≥ 10 × IV_probe ⇒ 才可说"ACK 吃掉探测价值"`，
  那句话在字面上有三个自洽读法（`IV_probe` 是 L1 还是 L2 的？`IV_ack` 是 ACK 的值还是"ACK 臂下的探测值"？），
  且**按任一读法都不能直接得到该结论**。本卡把它**唯一化为 `survival` 一个数**，
  并把 `IV_ack / IV_probe_L2` 作为**并列读数**报出。这是跑前修订，登记在 §7-1。**

## 3 判据（跑前写死，逐条给否定条件）

**`P-STRUCT`（结构预测，先于任何读数）**：`b=8`（只够 1 次发送）上
`A0p == A0` 且 `VL1 == VL2`（绝对差 `≤ 1e-13`）⇒ `survival(b=8) = 1`。
理由：付完 8 刻度后 `b=0`，剩下的槽**不允许发送**；而终值只依赖 `q·ΣP`，不依赖 `(m,v)`
⇒ ACK 拿到的信道信息**没有下游决策可用**。
★ 若这条不成立 ⇒ **`L1` 分支接错**（或 ACK 信息漏进了 `P` 之外的量），
判 `WIRING-SUSPECT-B8` 且**本轮所有 `b=16` 读数一律不得使用**。

**`P-A`（探测有没有价值）**：`IV_probe_L2` 在三档 `n_m` 上
- 全部 `≤ 1e-12` ⇒ `PROBE-WORTHLESS-AT-N1`：该实例判掉，走 §4 否定条件。
- 至少一档 `> 1e-12` 且符号在三点一致 ⇒ 继续 `P-B`。
- 符号在三点翻面 ⇒ `GRID-UNRESOLVED`，只报区间，不下判词。

**`P-B`（主判：ACK 是否吃掉探测价值）**：以 `IV_probe_L2(n_m=33)` 为分母（`n_m` 最细档），
并要求 `n_m∈{17,33}` 的 `survival` 差 `≤ 0.30`（否则报 `GRID-UNRESOLVED`）：

| `survival` | 判词 | 可说的话 |
|---|---|---|
| `≤ 0.10` | `ACK-EATS-PROBE` | 免费 ACK 在场时，耗槽探测的价值只剩 ≤10% |
| `∈ (0.10, 0.90)` | `ACK-PARTIALLY-EATS-PROBE` | 只报区间 + 三点，不说"主要/次要" |
| `≥ 0.90` | `ACK-DOES-NOT-EAT-PROBE` | 两种信息**近似正交**（各自独立有用） |
| `> 1 + 1e-6` | `ADF-BREAKS-MONOTONICITY` | **归因于近似**，不下物理判词（见 `G-MONO`） |

**`P-C`（ACK 本身有没有价值）**：`b=8` 上 `IV_ack` 必须 `≤ 1e-13`（与 `P-STRUCT` 同源）；
`b=16` 上若 `IV_ack ≤ 1e-12` ⇒ `ACK-WORTHLESS-AT-B16`：**这说明"2 次发送之间用不上信道信息"**，
而不是"ACK 没用"——必须同报 `VL2` 与 `A0` 的差，证明确实有发送决策可做。

**`P-D`（`τ` 方向）**：固定 `b=16`，`survival(τ)` 不预设单调。
`τ=4`（3 槽、2 发送）上若 `IV_probe_L2 ≤ 1e-12` ⇒ 该点记 `unmeasured-structural`，**不记 0**。

## 6 不许说的话（跑前写死）

1. 不许把 `VL1` 的读数叫"L1 最优"：L1 的信道信念用**假定密度滤波（ADF，单高斯矩匹配）**近似，
   它是 L1 语义的**可算实现**，不是 L1 的精确贝叶斯最优控制。
2. 不许把 `IV_ack` 当"信息价值上界"或"探测价值的上界"。
3. 不许把本轮 `n=1` 的 `IV_probe*` 与 R4–R5 的 2 用户 L2 数值**相减或相除**（跨实例、跨对象层级）。
4. 不许写"ACK 无用"：`P-C` 的零只能读成"在这个窗口/预算里，发送之间没有可利用的信道信息"。
5. 不许写"首次"：N0/N1 已占两项结构；本轮定位仍是**口径层 + 实测层 + 对比层**。
6. 不报 `mean±std` 或置信区间（确定性 DP，无随机性）。
7. 不许把 `p=0` 叫"免费"而不说清：**免的是量子，不免槽位**。

## 7 与 STATE §7.2 的偏差登记（跑前）

1. ★★★ **判据方向**：STATE 写 `IV_ack ≥ 10 × IV_probe ⇒ ACK 吃掉探测价值`。
   按 §1 的推导，"吃掉"只能是 `survival = IV_probe_L1/IV_probe_L2 → 0`；
   原句在三个读法下都不能得到该结论（且符号相反）⇒ 唯一化为 `survival` 一个数。**判据方向属跑前修订。**
2. ★★ **`α=2.5` 不适用**：`n=1` 没有用户间噪声比这一维；不写 `α`，只写 `σ_w=(0.02,)`。
3. ★★ **`ρ=0.999` 是新条件**：STATE §7.2 没指定 `ρ`，而 `mainline_config()` 的 `rho_panel[0]=0.85`。
   短记忆下 ACK 的信息活不过一个槽 ⇒ 必须换世界（新变体 `CW-POMDP-v1.4-ack`，只换 `rho_panel`）。
   **不做 `ρ` 扫描**，因此本卡结果**不能**与 R4–R5（`ρ=0.85`）直接比。
4. ★ **`w-grid` 的实现定义**：STATE 写"状态 `(t,P,m,v,b,w-grid)`；`w-grid∈{9,17,33}`"。
   本卡把它落到**两处离散化**并分别报：`m` 的网格 `n_m∈{9,17,33}`，
   以及 ADF 参考积分的标准化网格 `z∈[-6,6]` / `dz=0.025`（481 点，`G10-ck` 加密到 961 点核对）。
   `v` **不离散**（保持精确），因此 `v` 的取值个数作为分辨率一并报出。
