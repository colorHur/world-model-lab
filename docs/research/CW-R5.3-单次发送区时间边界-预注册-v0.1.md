## §0 开工前对上游的一句话修正：**槽数不是 `τ`，是 `τ−1`**

STATE §7.1-1 与 R5.2 交付写「`τ=4` 有 **4** 槽、2 发送 + 1 探测 = 3 槽 ⇒ 有余槽」。读实现后我认为
这个计数**多了一格**：

```python
# experiments/cw_v1/r5_2_three_users.py:172-179（R5.1 同式）
def V(t, Pp, mm, vv, b):
    if t <= 0:  return 0.0
    ...
    if t == 1:  memo[key] = S; return S        # ★ t=1 直接返回终值，不产生任何动作
```

⇒ 可动作的时隙是 `t = τ, τ−1, …, 2`，**共 `τ−1` 个**；`t=1` 是纯终端。
`τ=4` 因此是 **3** 个动作时隙（2 发送 + 1 探测**恰好填满**，没有第五个时隙），不是"3 用了 4"。

**这条修正改变什么、不改变什么**（必须分开说）：

| | 改变 | 不改变 |
|---|---|---|
| R5.2 的**实测零** | 无 | `IV_paid ≡ 0` 逐位仍是事实 |
| R5.2 的**措辞** | 「有余槽却不用」→「**正好填满，无余量**」 | 结论方向（3 用户 `b=16` 不转正）不变 |
| 本轮判据 | `τ=2` 只有 **1** 个动作时隙 ⇒ 探测必然挤掉唯一一次发送 | — |

⇒ 本轮据此把 `τ=2` 的零**预先登记为结构性零**（`STRUCTURAL-ZERO`），**不当信息价值证据**；
并且把它当**负控**用（若 `τ=2` 出现非零，说明我对时隙的理解错了）。

## §1 为什么这一轮的轴是 `τ` 而不是预算或价格

R5.2 把分界定在「**预算恰好只够一次发送**」（`b=8`），但那个分界只在 `τ=4` 一个窗口上被测过。
它有两种可能的解释，**必须用 `τ` 轴分开**：

- **H1（时隙论）**：`b=8` 的正例需要「至少 2 个动作时隙」才能存在（1 探测 + 1 发送）⇒ 只要 `τ≥3`
  就该出现，且窗口越长、择时/择人余地越大 ⇒ **`IV` 随 `τ` 非降**；
- **H2（巧合论）**：`b=8` 的正例是 `τ=4` 这一档的巧合（例如恰好只剩一次时机价值）⇒ 换 `τ` 会翻零。

R5.2 的 3 用户 `b=16` 零格**不能**区分 H1/H2（它换了预算与用户数，没换窗口）。
本轮把 `b` 与 `p` 全钉死，**只动 `τ`**，这是唯一能分开 H1/H2 的单变量设计。

★ 注意一个**结构事实**（写卡时由动作集包含关系推出，不看数据）：付费臂的动作集**包含**无探测臂的动作集
（`HOLD`/`SEND` 在付费臂里照样可选），且 `A0` 与 `V_paid` 是同一个 `V` 函数在不同动作集上的最小值
⇒ **`IV = A0 − V_paid ≥ 0` 恒成立**（机器上可能因舍入出现 `−1e-17`）。所以本轮**不存在"负 IV"**，
唯一能推翻 H1 的形态是**零**或**幅度下降**。

### 2.3 为什么把 `p=0` 当主档而不是 `p=1/4`

`τ` 轴要问的是"窗口够不够用"，不是"价格多低才买得起"（那是 R5.0/R5.1 已收口的）。
`p=0` 是**唯一**让探测不挤掉发送档的价格（R5.1 §7.5：整数量子预算下 `p∈(0,1]` 恒吃一整次发送）。
用 `p=1/4` 会把"窗口"和"预算"两个因子混在同一个零里 ⇒ 主档必须是 `p=0`，`p=1` 单列结构负控。

## §3 可证伪预测（跑前写死；任何一条被推翻都要原样上报）

- **`P-A'-1`（结构负控）**：`τ=2` 上 2 用户与 3 用户的 `IV_paid ≡ 0` **逐位**（`t=1` 无动作 ⇒ 探测挤掉唯一发送）。
  **推翻条件**：任一格非零 ⇒ 我对"`τ−1` 个动作时隙"的理解错，**本轮所有与 `τ` 有关的解释作废**。
- **`P-A'-2`（主）**：`τ ≥ 3` 上 2 用户与 3 用户的 `IV_paid` **逐格 > 1e-12**，且
  `IV(τ)` 在 `τ=3,4,5,6` 上**不出现超过分辨率的下降**。
  - 「分辨率」定义（**跑前写死**）：同一 `(arm, τ)` 上 `n_m=65` 与 `n_m=129`（及 `257`）之间的
    **最大相对差** `max|IV_i − IV_j| / max(IV_i, IV_j)`。下降幅度 ≤ 该值 ⇒ 记「不可分」，不记下降。
  - **推翻条件 ①**：`τ≥3` 出现任一零格或 ≤ `1e-12` 格 ⇒ H1 收窄（"1 探测 + 1 发送 ≥ 2 时隙就够"**不成立**）。
  - **推翻条件 ②**：出现**超过分辨率**的下降 ⇒ 「窗口越长越值钱」不成立（`P-A'-2` 的单调半句错）。
- **`P-B`（跨轮身份锚）**：2 用户、`τ=4`、`b=8`、`p=0` 必须**逐位**复现 R5.2 产物
  `cw_r5_2_three_users_20261026T162053_ed05ba8445708e56/r52.json` 的
  `IV_paid = 3.1456507883025064e-04`（`n_m=129`）与 `3.1456406290131245e-04`（`n_m=257`），
  以及 `A0 = 0.0944`（两档同值）。**锚值从产物 JSON 读，不手抄**（R5.2 §9-4 教训）。
  不逐位 ⇒ 本轮口径变了，主面板作废。
- **`P-C`（读数必须被用上）**：`drop_obs` 变异（`m' ← ρ·snap(m)`，其余不动）必须让**所有正格**塌到
  `≤1e-12`，**且**该变异必须真的改变至少一格的数值（否则变异无分辨力）。R5.2 在 3 用户 `b=16` 上
  `dV=0.0`（变异无分辨力），本轮在 `b=8` 上必须恢复分辨力。
- **`P-D`（选人 vs 择时）**：对称臂（`α=1`）在 `b=8` 上 `IV ≤ 1e-12`。
  **推翻条件**：非零（哪怕小）⇒ 单次发送区的价值里**有"择时"成分**，R5.2 §7.1-2 的
  「价值来自收件人选择」这条解释要拆成两项；**但若只在慢衰（`ρ≥0.98`）出现，不得外推到默认 `ρ`**（R4.1 已测）。
- **`P-E`（结构控制）**：`struct_p1`（`p=1`、`b=8`）**逐位零**；且 `A0` 对 `b` 单调（`A0(b=8) ≥ A0(b=16)`，
  `τ=2` 处**取等**、`τ≥3` 处**严格**）—— 后者是「动作时隙 = `τ−1`」的独立数值证据。

**不预言"必有正例"，也不预言幅度。** 幅度只报三点 `n_m` 的区间与分辨率，不报点值当"定律"。

## §5 规模规则（**先算整腿，再定 `n_m`**）

R4.2 教训：`memo` 在**腿内跨格累加**（本轮腿 = `(arm, n_m)` 下的全部 `τ` 与 `p`），单格探针系统性低估；
R5.1 教训：**越便宜越算不动**（`p=0` 时探测在每个时隙都可选，`21` 个 GH 分支逐层复制）。

- 规模探针：`τ ∈ {2,3,4,5,6}` **升序单跑**，`n_m ∈ {33,65,129,257}`，臂 = `2u_b8_p0` 与 `3u_b8_p0`；
  每腿跑该腿全部 `τ` 格；记录 `n_states` / `sec` / `capped`；`STATE_CAP = 6e6`。
- 规模探针**不是判据**，只为定 `n_m` 与 `τ_max`；**撞顶就报实测并降 `τ_max`**（判据不改、面板不缩）。
- 规则：主面板 `n_m` 取**满足以下两条的最大三点** ——
  ① 该 `n_m` 上 `3u` 与 `2u` 两条腿（含全部 `τ`）`n_states ≤ 3.0e6`（留一半余量）；
  ② 该点 `capped=False` 且 `sec` 有值。
- 若 `τ=6` 在最小 `n_m` 上撞顶 ⇒ `τ_max` 降到实测最大可行档，判据里的 `τ=3..τ_max` **原样适用**，
