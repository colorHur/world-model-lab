## §1 问题（一句话）

在同一开发面板、同信息权限下，`dp` 臂（世界模型值函数 + 冻结 `p̂`）与 `paced` 臂的任务侧差异，
能否被一个**机械量**（不经 `x̂`、不读 `cost_est`）分辨出来；若可分，**逐用户方向是否一致**。

## §2 为什么要换量：旧量的两处**机械缺陷**（可证，不依赖任何效应估计）

- **D1 末端单帧**：`mean_task_aoi` 只在 `T` 时刻取一次 `telemetry` ⇒ 每格只有 **2 个整数**（两个用户），
  256 个时隙的时间信息全部丢弃。同一臂跨 seed 从 3.5 跳到 18.5，**不是效应，是采样点太稀**。
- **D2 剔除未服务用户**：`-1`（`stamp<0`，从未送达）被 `if a >= 0` 过滤掉 ⇒ **用户越被饿死，它越不进指标**。
  这是 R17「不能用总平均隐藏受损用户」的**机制级版本**：不是聚合方式选得不好，是分母把受损者删了。

★ 两条都能用**合成数据**当场证明（G1/G1b 闸），不需要跑任何 episode。

## §3 新量定义（全部由逐槽记录推导；**纯记录扩展**，不改决策行为）

| 量 | 定义 | 说明 |
|---|---|---|
| `aoi_tavg_by_user[i]` | 用户 `i` 在全部时隙上 `task_aoi` 的**时间均值**，只统计 `stamp>=0` 的时隙 | 主量 |
| `n_unserved_slots_by_user[i]` | `stamp<0` 的时隙数（从未送达过） | 同报 |
| `n_never_served` | 全期未送达的用户个数 | **不饿死的守卫** |
| `aoi_final_by_user[i]` | 末端快照（= 旧 `mean_task_aoi` 的两个分量） | 与旧证据对账用 |
| `aoi_max_by_user[i]` | 期内最大陈旧度 | 饥饿守卫 |
| `n_delivered_by_user[i]` / `n_attempted_by_user[i]` | 由 `SlotRecord.data_delivered/action/user` 计数 | 副量 |

- 旧 `mean_task_aoi`（`EpisodeResult` 字段）**保留不动、语义不改**，历史证据一致性优先。
- 全部新增量是**加法**：不参与任何策略决策、不消耗随机数、不改 `cost_est/cost_true`。

## §4 判据（看数前写死）

- **U1 口径闸**：`aoi_final_by_user` 的 `>=0` 分量均值必须与旧 `mean_task_aoi` **逐位相同**（`abs_diff ≤ 1e-12`）；
  不等 ⇒ 新量的口径没接对 ⇒ 本轮全部作废（不是"调一调"）。
- **U2 身份闸**：重跑的 `paced16|100|2001` 与 `dp16|100|2001` 必须与 R1.7.6 入库 cell 的
  `cost_est / cost_true / n_delivered / n_attempted / n_probe / policy_trace_hash` **逐位相同**。
  不等 ⇒ 说明这次改动**不是**纯记录 ⇒ 停，只交付"改动有副作用"这一条。
- **U3 主判据（逐用户 × 时间平均）**：对每个 `(ep, user)`：
  `r_j = aoi_tavg_by_user_dp[j] / aoi_tavg_by_user_paced[j]`，`j = 1..4` 个 seed。
  - **可分** = `4/4` 同向 **且** 配对差 bootstrap 95% CI（`B=20000`，`rng=20261024`）排除 0
    **且** `|中位 r − 1| ≥ 0.20`。
  - ★ `n=4` ⇒ **必须 4/4**。依据 R1.7.8：`n=8` 的 `7/8` 只有 `p=0.070`，不是显著；
    `n=4` 的 `3/4` 更不算。**不许**用"方向已定"代替 `p`。
- **U4 一致判据**：同一 `ep` 两个用户的 `r` 方向相反 ⇒ 判 `MECH-TRADE`。此时**必须逐用户报**，
  禁止任何"改善/变差"的整体表述（R17）。
- **U5 副量同向性**：`n_delivered_by_user` 的比值符号必须与 U3 的 `r` **相反**
  （送达少 ⇔ 陈旧高）。若同号 ⇒ 判 `MECH-INCONSISTENT`（说明 aoi 与送达计数之间还有别的机制，
  在搞清楚之前不得把 aoi 当"任务侧唯一读数"）。
- **U6 地板**：同臂（`paced16` 内）跨 seed 的 `aoi_tavg_by_user` 对称相对差中位。
  报 **效应 / 地板** 比值；地板 ≥ 效应 ⇒ 该格 `UNRESOLVED`。
  ★ 地板与效应必须用**同一个尺度**（`sym`），且分母子集要写清（R1.7.8 教训 #102）。

## §5 R1.7.4 `TAILS-SWITCH` 的语义冲突：处置（本轮起生效，不改历史）

- **两个量测的不是同一构念**：`G8a` 的 CV 测**资源在时间上的均匀度**（"配速"），
  `G8a2` 的 aoi 测**任务结果**（陈旧度）。
- **它们的反向是结构性的，不是判据打架**：把帧集中到"需要它的时刻"必然抬高 CV、降低 aoi；
  反之"平均撒帧"压低 CV、抬高 aoi。任何"CV 低 且 aoi 低"的组合在这个协议里**不是被禁止，而是需要额外资源**。
- **处置**：
  1. `CV` 降级为**机制读数**（报、不判）；
  2. "配速"这一构念改由**饥饿量**承担：`n_never_served` 与 `aoi_max_by_user`。
     它们与 aoi **同向**（越小越好）⇒ **不可能**与 aoi 反向冲突，语义冲突从根上消失；
  3. **不修改** `plan_gates` 的 `G8a/G8a2` 实现与阈值（历史证据必须可复现）；
     旧的过/不过记为历史，新判据集合只在 R1.8+ 生效。
- ★ 自证伪预案：若"饥饿量"与 aoi 在实测中再次反向 ⇒ 说明 aoi 本身有问题（不是守卫有问题），本轮判 `MECH-INCONSISTENT`。

## §6 否定条件（什么结果算"换量也没用"）

- **N1**：4 个 `(ep, user)` 格中 **≥3 格** `UNRESOLVED` ⇒ `MECH-UNRESOLVED`。
  此时下一步**不是**换第五种切片，而是"加 episode"（须先报预算）或改协议。
- **N2**：≥2 个 `(ep, seed)` 对上两用户 `r` 方向相反 ⇒ `MECH-TRADE`，只许写"交易"。
- **N3**：U2 身份闸不过 ⇒ 本轮**不出任何效应结论**，只交付"记录扩展有副作用"的更正。
