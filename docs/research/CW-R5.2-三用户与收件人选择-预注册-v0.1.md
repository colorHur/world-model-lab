## §0 开工前对任务书的一句话修正（我的判断，不是执行）

STATE §7.2 把待检验的机制写成「**人人能被服务时读数无用**」。读 R5.1 的原始读数后，我认为这句话
**不是**数据能支持的形态，正确形态是：

> **读数的价值来自「收件人选择」；选择自由度 = `可发送次数 < 可服务用户数`。
> 当 `发送次数 ≥ 用户数` 时，收件人被预算强制确定，读数只剩「时机」信息，而时机在本实例里无价值 ⇒ `IV = 0`。**

依据（**都是 R5.1 已落盘的读数，本轮零新算**，`results/cw_v1/cw_r5_1_price_ticks_20261026T140546_b8a5792a24eba04d/r51.json`）：

| 配置 | `b`（刻度） | 发送次数 vs 用户数 | `p=0` 的 `IV_paid` |
|---|---|---|---|
| `α=2.5, τ=4, P=0.01` | `8` | 1 < 2 | **`2.544453e-4`**（`A0=9.44e-2`） |
| 同上 | `10` | 1 < 2 | **`2.544453e-4`** |
| 同上 | `16` | 2 = 2 | **`0.0`**（逐位） |

⇒ 「读数无用」不是由"服务覆盖满"造成的**新**现象，它在同一目标函数内就已经随 `发送次数/用户数` 的
比值翻面了。R5.1 把 `b=8` 那一格只当 `T-4` 的**活体对照**（"零不是没接线"）上报，**没有**把它当成机制证据 ——
这是本轮要改的登记口径，不是新数据。

**修正的后果**：本轮的 3 用户格**不是**"第一次看见正例"，而是**同一条律的第二个比值点**
（`2/3` 与 `1/2` 都 < 1，`2/2` 与 `3/3` 都 = 1）。所以判据要能同时解释 `/2` 与 `/3`，不能只解释 `2/3`。

## §1 为什么必须换 `n_users` 而不能只调预算

`b=8`（2 用户 / 1 发送）已经给了比值 `<1` 的正例，但它的正例有一个**替代解释**：
`b=8` 是**预算极紧**档，`ΔV_send = A0(10) − A0(2) = 0.003`，一次发送的相对价值是 `b=16` 档的若干倍。
「值钱」可能来自**稀缺**（预算少），而不是**选择**（发送次数少于用户数）。

⇒ 只有把**预算和发送次数固定住**、只加用户，才能把「稀缺」和「选择」分开：

- 3 用户 `b=16`（2 发送）：发送次数与 2 用户 `b=16` **完全相同**（都是 2 次），只多一个用户 ⇒
  若仍为零，则"选择自由度"这条律**不成立**；
- 若转正，则它和 `b=8` 的正例是**同一条律在另一个比值上**，且"稀缺"解释被同一个 `b=16` 的 2 用户零格排除。

**这条对照正是本轮唯一值得花 CPU 的东西**，所以 §2 的面板必须包含**同引擎同预算的 2 用户对照**。

## §2 面板（跑前写死）

固定：`α=2.5`、`P=0.01`、`κ=1`、`τ=4`、`gh_n=21`、`σ_csi=σ⋆=1e-9`、`V_PRIOR=1.0`、
`A=(1,1,…)`、`B=0.32`、`σ_meas=0.20`、`q=1.0`（= `bounded_plant()` 的既有值，一字节不改）。

### 2.1 主面板（判定用）

| 轴 | 取值 | 说明 |
|---|---|---|
| `n_users` | `2`、`3` | `2` = **同引擎同预算对照**（P-B）；`3` = 主件 |
| `sigma_w` | 2 用户 `(0.02, 0.05)`；3 用户 `(0.02, 0.05, 0.05)` | 3 用户**追加的是第二个高噪用户**（见 §2.3 的理由） |
| `b_ticks` | `16` | = 2 量子 = **2 次发送**；2 用户时 `2/2`，3 用户时 `2/3` |
| `p` | `1`、`1/4`、`0` | ⇒ `probe_ticks = 8, 2, 0`；`p=0` 是免费极限 |
| `n_m` | **三点**，由 §5 的规模规则定 | 不允许单点报幅度（R4.1 教训） |

格数：`2 × 3 × 3 = 18` 格。

### 2.2 镜像臂与构成臂（机制用，单点 `n_m`，不当幅度用）

| 臂 | 配置 | 预测（§3） | 作用 |
|---|---|---|---|
| **镜像** | 3 用户 `b=24`（3 发送 = 3 用户），`p∈{0,1/4}` | 预测 `IV=0` | 同一条律的另一侧（`/`=1） |
| 镜像·2 用户 | 2 用户 `b=24`（3 发送 > 2 用户），`p∈{0}` | 预测 `IV=0` | 超额覆盖也不必选 |
| **构成** | 3 用户 `sigma_w=(0.02,0.05,0.02)`、`b=16`，`p∈{0,1/4}` | 未预测（探索） | 回答"是不是换了哪个人" |
| **稀缺锚** | 2 用户 `b=8`、`p=0`，三点 `n_m` | 预测 `IV>0` | R5.1 的 `2.544453e-4` 在三点上的符号与幅度 |

### 2.3 为什么第 3 个用户取 `σ_w=0.05`（而不是 `0.02`）

`P_i` 的首值与增长都由 `σ_w[i]` 决定，而 DP 的成本是 `q·ΣP_i` ⇒ `P_i` 是**收件人排序的唯一确定性依据**
（信道信念在无探测时对三个用户**完全相同**：`m=0, v=1`）。

- 若第 3 个用户取 `0.02`（低噪），它的 `P_3` 始终最小 ⇒ 它**本来就不会被选中** ⇒ 探测无从改变收件人，
  得到的零会是"加了一个不会被选中的人"的零，**不是**机制的反例；
- 取 `0.05` ⇒ 用户 2 与用户 3 在 `t=0` **完全并列**（`P=0.01`、`m=0`、`v=1` 全同）⇒ 2 次发送要在
  **两个并列候选**里选 1 个 ⇒ 决定权**只能**来自信道读数。

⇒ 这是"选择自由度"能被**最大化**的构成，也是我**主动选择**的构成。`(0.02,0.05,0.02)` 单列成 §2.2 的构成臂，
用来回答"是不是换了哪个人"这个问题；**它不进主判据**。

## §3 可证伪预测（跑前写死；任何一条被推翻都要原样上报）

- **`P-A`（主）**：3 用户 `b=16` 至少在 `p=0` 与 `p=1/4` 上出现 `IV_paid > 0`，且**三点 `n_m` 符号一致**。
- **`P-B`（对照/身份锚）**：2 用户 `b=16` 在 `n_m=17` 上必须**逐位**复现 R5.1 的 `IV_paid = 0.0` 与
  `A0 = 9.142381e-02`。不逐位 ⇒ 本轮口径变了，主面板作废。
- **`P-C`（镜像）**：3 用户 `b=24`（3 发送 = 3 用户）`IV_paid = 0`（逐位或 ≤ `1e-12`）。
  **推翻条件**：显著为正 ⇒ 「`发送次数/用户数`」这条律错，零另有原因。
- **`P-D`（稀缺 vs 选择）**：3 用户 `b=16` 的 `IV_paid` 若为正，**不得**用"预算更紧"解释 ——
  因为同一 `b=16` 下 2 用户为 `0`（`P-B`）。**推翻条件**：3 用户 `b=16` 也为 `0`。
- **`P-E`（价格单调）**：固定 `(n_users, n_m)`，`IV_paid` 随 `p` 下降**不减**（动作集嵌套；
  `V` 不增 ⇒ `IV = A0 − V` 不减）。**方向先从数学推，不看数据再定**（R5.0 §7.5-1 的教训）。
- **`P-F`（读数必须被用上）**：把探测读数**丢弃**（`drop_obs` 变异：`m' ← m`，其余不动）后，
  所有正格必须塌到 `≤1e-12`；且该变异必须**真的改变**至少一格的数值（否则变异无分辨力）。

**不预言"必有正例"，也不预言幅度。** 幅度只报 `n_m` 三点的区间，不报点值。

## §5 规模规则（**先算整腿，再定 `n_m`**）

R4.2 教训：`memo` 在**腿内跨格累加**，单格探针系统性低估；R5.1 教训：**越便宜越算不动**
（`p=1/4` 比 `p=1` 状态多）。

- 规模探针：`n_users ∈ {2,3}` × `n_m ∈ {5,7,9,11,13,17}` × `p ∈ {0,1/4}` × `b ∈ {16,24}`，
  **每腿只跑该腿全部格**，记录 `n_states` / `sec` / `capped`；
- 规模探针**不是判据**，只为定 `n_m`；
- 规则：主面板 `n_m` 取**满足以下两条的最大三点** ——
  ① 3 用户 `b=16` 的整腿（含三个价格）`n_states ≤ 3.0e6`（留一半余量给 `STATE_CAP=6e6`）；
  ② 该点能算完（`sec` 有值、`capped=False`）。
- 撞 `STATE_CAP` ⇒ **报实测并降 `n_m`**；面板不缩、判据不改。若连 `n_m=5` 都撞 ⇒
  判 `NO-VERDICT-INSUFFICIENT-GRID` 并如实写"3 用户在 `τ=4` 上不可枚举"，**不拿 2 用户的结果顶替**。
- `b=24` 臂若撞顶 ⇒ 单列 `capped`，`P-C` 记"未测"，**不写成"零"**（R5.0 教训：`NaN` 一律分流成"没测到"）。

## §7 不做什么

- **不开训**，不调噪声/不稳定性/指标去追正收益，不重跑旧 P3。
- 不把 3 用户的 `IV` 与 2 用户的 `IV` **直接相减**当"多一个用户值多少"：两者的目标函数是
  `q·ΣP_i`，用户数不同 ⇒ **跨实例**。只报各自的值与 `IV/A0`，并明写"跨实例不相减"。
- 不把受限窗口 DP 的读数写成"控制成本降 X%"（三类对象分登记，R5.0 §1.4）。
- 不用单点 `n_m` 的幅度说话；不把 `b=24` 的 `capped` 写成零。
- 不把本轮当"价格边界"：价格只取 `{1,1/4,0}` 三点，只为机制，不为边界。
