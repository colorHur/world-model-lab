## 1 问题（一句话）

R1.5 的规划参考**不会配速**：`B/T=0.5` 时 128 帧在**前 128 槽**花光，
`send_profile`（8 个 1/8 窗口的资源动作数）= `[31.25, 31.25, 31.13, 29.75, 4.63, 0, 0, 0]`，
`mean_task_aoi` **122.8**（`periodic2` 是 7.0），逐格配对比值 1.374 / 2.024 / 1.017 / 1.892
（`ratio = candidate / baseline`，`<1` 更好）。配速残差比待测效应（+0.003…+0.013）大一个数量级，
且 `G4`（`M` 加倍稳定性，成本相对差中位判据 ≤10%）实测 **27.7%**。

机制（R1.5 §3.3 已实测）：尾部估计 `_terminal` 假设"今后**再无**观测"，
`A=1` 时 `Σ P_k` 是 `steps·P + σ_w²·steps(steps+1)/2`（**二次增长**）⇒
①任何一帧"现在发"都显得极贵；②花掉的预算在尾部估计里**没有价格**（只禁止超额，不影响估值）
⇒ 前紧后松。这不是"采样不够"，是值函数本身错。

## 2 本轮唯一假设

**H（R1.6-1）**：把尾部估计从"再无观测"改成"剩余预算 `b` 按可负担速率
`m = steps·n_users / b` 均匀铺开"的**稳态循环**估计，会让参考自己配速，
并使一次决策对抽样噪声的依赖显著下降（`G4` 通过）。

这条假设是**实现级**的：它判的是"值函数是否遗漏了预算的机会成本"，
不是"主动测量有没有价值"。

## 5 预写公式（对账用，避免"跑完再解释"）

均匀配速下，用户 `i` 的刷新间隔 `m`（步）。设 `a² = A_i²`、`s² = σ_w,i²`、`c = σ_meas²`、
`k = a^{2(m-1)}`、`G = s²·(k-1)/(a²-1)`（`A=1` 时 `G=(m-1)s²`）。循环不动点

```
P_post = P_b·c/(P_b+c) + s²          （送达 + 量测更新后）
P_b    = k·P_post + G                （两次刷新之间自然增长）
⇒ P_b = ½[W + sqrt(W² + 4(G + k·s²)·c)],  W = G + k·s² + (k-1)·c
⇒ P̄ = (P_post + P_b)/2
```

`A=1` 闭式代入：`W = m·s²`、`P_b = ½[m s² + sqrt(m²s⁴ + 4 m s² c)]`。

当前 `P` 低于 `P_b` 时，先"走到 `P_b`"用 `w` 步（`w = min(m, (P_b−P)/s²)`），
其余按 `P̄` 计；`P ≥ P_b` 时 `w=0`，首步仍按 `P` 计。

**量级代验（先算，不等跑）**：`B/T=0.5`、`T=256`、`n=2` ⇒ `b=128`、`m=4`；
用户 0（`s²=4e-4`、`c=4e-2`）⇒ `P_b = ½[1.6e-3 + sqrt(2.56e-6 + 2.56e-4)] ≈ 8.8e-3`，
`P̄ ≈ 8.2e-3`；用户 1（`s²=9e-4`）⇒ `P_b ≈ 1.3e-2`。⇒ 每步 `q·ΣP` 约 `0.022`，
与 `periodic2` 实测 `cost_true ≈ 0.055`（含 `x²` 与 `r·u²`）**同量级**。
若实测 `cost_true` 与这个代验差一个数量级，先怀疑我的公式，不怀疑被测物。

### 7.1 `G8c` 的对照物换了（原判据 FAIL 后）

- **原写法**：闭式 vs 逐步模拟**同一条均匀时间表**，`b×steps×P0` 9×3×3 网格，相对差 ≤2%。
- **实测**：FAIL，最差 **8.47×**（`b=4, steps=250, P0=1.0`），另有 `b=1` 一片 2.65×。
- **查明原因（两条都不是算术错）**：
  ① `P0 ≫ P_b`（冷启动）时闭式走"一步压到循环均值"的**约定**（`w=0` 分支），
     而逐步模拟铺的是"按 `m` 均匀铺开"的时间表 —— 两者是**不同模型**；
  ② `m ≥ steps/2` 时尾部不足两个周期，"均值代替逐相位值"的相位误差压过要判的算术误差。
- **改法**：改为**稳态循环均值对账** —— `m` 取整数、初值取循环均值，
  比 `_paced_sumP(·)/steps` 与 4096 步长程模拟的后半段均值，相对差 ≤1%，`m∈{2,4,8,16,32}`。
- **第一次改完仍然 FAIL，是闸自己错**：传了 `steps=1024`，而 `_paced_sumP` 内部把
  `steps` 截到 `_TERM_MAX_STEPS=400`，闸却按 1024 做除法 ⇒ 系统性偏低
  （`2.3488/1024 = 2.29e-3`，看着像"闭式低于循环下界"的怪系数）。改 `steps=400` 后 PASS
  （最差 0.82%，在 `m=32`）。
- **仍然不判的**：冷启动（`P ≫ P_b`）与短尾（`m ≥ steps/2`）两个近似**没有任何闸覆盖**，
  它们是被记录的近似，写在 `g8c_closed_form` 的 docstring 里。⇒
  **不许**用本轮结果声称"`_expect_after` 在 episode 早期时隙数值准"。

### 7.2 新增 `G8d`：值函数对预算严格递减（**新判据，且 FAIL**）

- **为什么加**：`M1` 变异（探测不学任何东西但照扣钱）**抓不住**（`n_probe=18`），
  `G4` 动作一致率又从 0.910 崩到 **0.482**。查下去是同一个根因：
  `m = round(steps·n/b)` 是整数 ⇒ `b` 在一个区间内变，`m` 不变，尾部估计**逐位相同**
  （实测 `steps=128` 时 `b=120…135` 全等）⇒ "花掉一帧的机会成本"在值函数里是 **0**。
- **判据**：未饱和区（`b ≤ steps`）上，相邻 `b` 的估计值**平坦比例 ≤10% 且无上升**。
- **实测**：`n_pairs=128`、`n_flat=100`（**78.1%**）、`n_up=0` ⇒ **FAIL**。
- **这条闸是负资产还是正资产**：它是本轮**最有信息量**的结果 —— 它把"配速修好了残差、
  但预算的价格还没真正进值函数"钉成了可复算事实，并同时解释了 `M1` 抓不住与 `G4` 崩掉。
  ⇒ 下一轮的入口不是"再调 M"，而是"让 `m` 连续化（相邻整数 `m` 的 `P̄` 线性插值）"。

### 7.3 `G1d` 的控制方向补齐（既有闸，非预注册条目）

- 原写法只**向上**加 `P̂`（+2.5/+12/+60），而在该时点动作为 `SEND(0)`、用户 0 本来就是
  `P̂` 最大者 ⇒ 把它弄得更贵，动作当然不变。**控制无分辨力**，`n_changed=0` 是闸的错。
- 改为加**向下**（`P̂×1e-3`）与**换人**（用户 1 +60）两个方向，保留原三档向上做对照。改后 PASS。
