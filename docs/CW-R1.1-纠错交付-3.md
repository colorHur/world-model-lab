## 3 G4 为什么 FAIL：三层，逐层实测

### 3.1 第一层（已修）：根动作之间没有真正配对

第一版按"每个根动作用同一 seed 新建生成器"。那只配对到**第一步**：第一步之后各分支
消耗随机数的次数不同，从第二步起各走各的路径。实测 `M=16` 帧一致率 **0.656**。
改法：一个时隙抽**一张**随机数面板 `_Draws`（按 `(步 k, 样本 m, 用户 i)` 预生成，
`udeliv / eps_meas / eps_csi / s_h / w / init_x / init_h`），5 个根动作**共用同一张表**，
任意两个根动作在同一 `(k,m)` 上看到**同一个**世界实现 ⇒ 变成配对差。
效果：一致率 0.656 → **0.910**。

### 3.2 第二层（已修）：尾部贪心用错剩余步数

`_greedy` 里终止估计用的是**根节点**的 `steps_left`，不是尾部当前步的剩余步数
⇒ 尾部终止权重被系统性放大（更爱发帧）。改成传 `steps_left-(k+1)` 后，
`n_probe` 从 22–41/集 掉到 1–3/集（说明先前那批探测**主要是这个偏差造成的**）。

### 3.3 第三层（**未修，本轮结论**）：近并列决定 × 路径依赖

即使配对 + 修 bug，`M` 32→64 的成本相对差仍是 20% / 54% / 105%。
机制：`1` 步贪心 + "无新信息"尾部对**什么时候**花这一帧几乎无差别
（与 P3-1 的"一帧的价值几乎与陈旧度无关"同源，`A=1` 时 `ΔP` 只差 1.2%），
但发帧时点决定后半段的漂移长度 ⇒ **目标函数平、结果陡**。
一次抽样翻转会让"预算耗尽的时刻"挪动几十槽，成本随之变 2–4 倍。

⇒ 这不是"再多采样几倍"能解决的（`M=128` 仍不稳，实测 0.074 / 0.302 两集）。
必须换值函数，见 §7。

## 5 口径更正（**看数前**做，理由是解析的）

预注册卡 §5 写「主指标 `cost_est_per_step`」。本轮开工第一件事就把它**改掉**，
理由是可复算的、与结果无关：

* 世界记 `cost_est = q·Σ x̂² + r·Σ u²`，而 `u = -K x̂` ⇒ 不发帧时 `x̂_{t+1} = (A−BK)·x̂_t`。
  `BOUNDED` plant 上 `K = 2.677078`、`A = 1` ⇒ **`A−BK = 0.143335`**，`x̂` 几何衰减。
* 实测（`plan_gates.G6`，40/40 集一致）：`HOLD` 的 `cost_est = 0.000000`，
  而 `cost_true = 3.076`。
* ⇒ `cost_est` 会**奖励"不发帧"**：什么都不做拿满分。拿它当主指标，
  相当于用"接收端以为自己付了多少"替代"实际付了多少"。

**新口径（写进 `plan_ref` 目标函数与证据 `disclaimer`）**：主指标 `cost_true_per_step`；
`cost_est` 只作诊断。规划器最小化的是**给定信念下真实代价的贝叶斯期望**
`q·Σ(P + x̂²) + r·Σu²`（= `E[cost_true | 信念]`，一阶恒等）。
★ 若目标函数也写成 `q·x̂²`（不含 `P`），SEND 的价值恒为 0 ⇒ 规划器退化成 HOLD，
那正是卡 §5 的 N3（实现缺陷），不是科学结论。

## 8 引用纪律（写给别人看的话）

  它不是上界、不是最优策略。
